# Project S Working Game Plan

## 문서 목적

이 문서는 Project_S에서 앞으로 기능 구현, 리팩터링, 기획 보강, 테스트 맵 제작을 진행할 때 공통으로 참조할 게임 기획 기준이다.

작업자는 세부 구현 전에 이 문서를 먼저 확인하고, 더 자세한 내용이 필요하면 아래 문서를 함께 참조한다.

- `Docs/Game_Planning_Overview.md`: 전체 기획 틀과 장기 결정 항목
- `Docs/MVP_Essential_Elements.md`: 1차 MVP 필수 요소와 완료 기준
- `Docs/ProjectS_Tilemap_System.md`: Unity Tilemap 기반 맵 시스템 기준

## 현재 게임 방향

Project_S는 PC 우선 개발을 목표로 하는 2D 탑다운 RTS 전략 게임이다.

현재 기준의 핵심 콘셉트는 다음과 같다.

```text
플레이어는 2D 전장에서 자원을 채집하고 기지를 확장하며,
병력을 생산해 실시간 전투와 상성 판단으로 AI 상대를 섬멸한다.
```

| 항목 | 기준 |
|---|---|
| 주 장르 | 전략 게임 |
| 보조 장르 | RTS |
| 시점 | 2D 탑다운 |
| 플랫폼 | PC 우선 개발, 모바일은 추후 대응 |
| 조작 | PC: 마우스 및 키보드 중심 |
| 플레이 형식 | 스타크래프트와 유사한 1대1 RTS 매치 |
| 1차 콘텐츠 | 플레이어 vs AI 1대1 매치 |
| 플레이어 목표 | 적 섬멸 |
| 권장 매치 시간 | 15~25분 |
| 최대 매치 시간 | 40분 미만 |
| 개발 범위 | 1인 개발 기준 MVP 우선 |
| 세계관 | 추후 결정 |
| 아트/사운드 | 추후 결정, MVP에서는 임시 리소스 우선 |

## 핵심 재미

이 게임의 재미는 다음 흐름에서 나온다.

```text
자원 생산
-> 유닛 생성 및 강화
-> 적과의 전투
-> 승리 시 기지 및 진영 확장
-> 더 많은 자원 생산
```

작업 시 우선순위는 콘텐츠 양보다 이 루프가 실제로 작동하고 재미있게 느껴지는지 검증하는 데 둔다.

## MVP 범위

1차 MVP는 아래 범위를 넘기지 않는 것을 기본으로 한다.

```text
플레이어 1명 vs AI 1명
진영 1개
테스트 맵 1개
자원 1종
본진 건물 1종
자원 채집 유닛 1종
전투 유닛 최소 3종
생산 건물 1~2종
간단한 AI
승패 판정
기본 UI
```

## MVP 필수 시스템

| 영역 | 필수 구현 내용 |
|---|---|
| 카메라 | 2D 탑다운, 이동, 줌 |
| 입력 | 마우스 선택, 드래그 박스 선택, 우클릭 이동/공격 |
| 맵 | 자원, 기지, 전투 동선을 검증할 테스트 맵 |
| 자원 | 최소 1종 자원 |
| 일꾼 | 자원 채집, 복귀, 반복 채집 |
| 건물 | 본진, 생산 건물 |
| 유닛 생산 | 건물에서 유닛 생산 |
| 전투 유닛 | 역할이 다른 최소 3종 |
| 전투 | 자동 공격, 사거리, 체력, 공격력, 공격 쿨타임 |
| 상성 | 간단한 유닛 간 강약 관계 |
| AI | 채집, 생산, 공격 타이밍, 방어, 승패 반응 |
| 승패 | 상대 모든 건물 파괴 |
| UI | 자원 표시, 선택 정보, 체력, 생산 버튼, 생산 상태, 승패 결과 |

## 유닛 기준

초기에는 유닛 수를 늘리는 것보다 역할이 분명한 3종을 먼저 구현한다.

| 유닛 유형 | 역할 |
|---|---|
| 기본 전투 유닛 | 평균적인 비용, 체력, 공격력을 가진 기준 유닛 |
| 빠른 돌격 유닛 | 빠른 이동, 기습, 근접 압박 |
| 원거리 유닛 | 긴 사거리, 낮은 체력, 거리 유지 중심 |

상성은 절대 승패가 아니라 위치, 수량, 컨트롤에 따라 뒤집힐 수 있어야 한다.

## 건물 기준

MVP의 건물은 아래 구조를 우선한다.

| 건물 유형 | 역할 |
|---|---|
| 본진 건물 | 일꾼 생산, 자원 반납, 주요 승패 조건 |
| 기본 생산 건물 | 전투 유닛 생산 |
| 보조 생산 또는 기술 건물 | 선택 사항, 필요 시 유닛 해금 또는 강화 |

복잡한 테크 트리와 업그레이드는 기본 루프 검증 이후로 미룬다.

## AI 기준

MVP AI는 고급 전략보다 매치 상대 역할을 우선한다.

AI는 최소한 다음 행동을 수행해야 한다.

- 일꾼을 생산하거나 유지한다.
- 자원을 채집한다.
- 생산 건물에서 유닛을 만든다.
- 일정 병력이 모이면 공격한다.
- 본진 또는 주요 건물을 방어한다.
- 승패 조건에 반응한다.

## 맵과 지형 기준

현재 구현은 Unity Tilemap 기반으로 RTS 플레이를 올릴 테스트 맵을 점진적으로 구성하는 방향이다.

맵 시스템은 아래 기준을 따른다.

- 격자 기반 2D 맵을 사용한다.
- 타일, 자원, 장식물, 스폰 지점은 격자 중심 기준으로 배치한다.
- 높은 땅, 낮은 땅, 오르막길, 단차 벽면은 게임 규칙에서 제외하고, 이동 가능/불가와 건설 가능/불가 타일로 구분한다.
- 자원 노드, 바위, 스폰 지점을 배치할 수 있어야 한다.
- 맵은 검증 가능해야 한다.
- 작업된 맵은 런타임에서 실제 게임 맵으로 사용할 수 있어야 한다.

현재 맵 시스템 작업 기준은 `Docs/ProjectS_Tilemap_System.md`를 따른다.

## MVP에서 제외할 요소

아래 요소는 기본 루프 검증 전까지 후순위로 둔다.

- 복잡한 세계관
- 고품질 아트
- 다수 종족
- 캠페인
- 멀티플레이
- 모바일 조작 최적화
- 고급 업그레이드 트리
- 안개 전쟁
- 랭킹 및 계정 시스템
- 고급 AI

## 권장 개발 순서

```text
1. 카메라와 테스트 맵
2. 유닛 선택 및 이동
3. 자원 채집
4. 건물 건설
5. 유닛 생산
6. 전투 시스템
7. 간단한 상성
8. AI 생산 및 공격
9. 승패 판정
10. UI 정리
11. 밸런스 조정
```

## 작업 시 판단 기준

새 기능을 추가하거나 기존 기능을 수정할 때는 아래 순서로 판단한다.

1. 이 작업이 RTS 핵심 루프에 직접 도움이 되는가?
2. MVP 범위 안에 있는가?
3. 1인 개발 기준으로 유지보수 가능한가?
4. PC 마우스/키보드 조작 기준에서 자연스러운가?
5. 테스트 맵과 AI 1대1 매치 검증에 도움이 되는가?

위 기준에 맞지 않는 기능은 문서화만 해두고 후순위로 미룬다.

## MVP 완료 정의

현재 기준에서 MVP는 아래 상태를 만족하면 완료로 본다.

```text
플레이어가 자원을 채집하고,
건물을 짓고,
유닛을 생산하고,
AI와 전투하여,
상대 모든 건물을 파괴하거나 패배할 수 있으면 MVP 완료로 본다.
```
