# Game Planning Overview

## 문서 목적

이 문서는 Project_S의 게임 기획 전체 틀을 정리한다.

MVP 필수 요소뿐 아니라, 이후 세부 기획 단계에서 결정해야 할 장르, 시스템, 콘텐츠, UX, 아트, 사운드, 플랫폼, 개발 범위를 함께 관리하기 위한 기준 문서다.

## 현재 확정된 방향

| 항목 | 내용 |
|---|---|
| 주 장르 | 전략 게임 |
| 보조 장르 | RTS |
| 시점 | 2D 탑다운 |
| 플랫폼 | PC 우선 개발, 모바일 추후 대응 |
| 조작 | PC: 마우스 및 키보드 / 모바일: 추후 결정 |
| 플레이 형식 | 스타크래프트와 유사한 RTS 매치 |
| 플레이어 목표 | 적 섬멸 |
| 핵심 재미 | 자원 수집, 기지 건설, 병력 생산, 실시간 상성 판단, 상대 제압 |
| 1차 개발 범위 | 1인 개발 기준, AI 1대1 매치 MVP |
| 세계관 | 추후 결정 |
| 아트 방향 | 추후 결정 |
| 사운드 방향 | 추후 결정 |

## 핵심 콘셉트

현재 기준의 한 줄 콘셉트는 다음과 같다.

```text
플레이어는 2D 전장에서 자원을 채집하고 기지를 확장하며, 병력을 생산해 실시간 전투와 상성 판단으로 AI 상대를 섬멸한다.
```

추후 세계관이 정해지면 아래 형식으로 보강한다.

```text
플레이어는 [세계관 속 역할]이 되어 [핵심 행동]을 반복하며 [감정적 경험]을 얻는다.
```

## 핵심 재미 요소

이 게임의 핵심 재미는 다음 흐름에서 나온다.

- 제한된 자원을 빠르게 확보한다.
- 자원을 어떤 건물과 유닛에 사용할지 판단한다.
- 상대의 병력 구성을 보고 상성을 파악한다.
- 실시간으로 병력을 이동시키고 교전한다.
- 승리한 전투를 바탕으로 기지와 진영을 확장한다.
- 확장된 자원력을 다시 병력과 기술 우위로 전환한다.

## 코어 루프

```text
자원 생산
-> 유닛 생성 및 강화
-> 적과의 전투
-> 승리 시 기지 및 진영 확장
-> 더 많은 자원 생산
```

MVP에서는 강화 시스템이 복잡하지 않아도 된다. 우선은 생산, 전투, 확장 흐름을 검증하고 이후 업그레이드나 테크 트리를 확장한다.

## 플레이 세션 목표

- 권장 매치 시간: 15~25분
- 최대 매치 시간: 40분 미만
- 프로토타입 단계에서는 실제 플레이 테스트를 통해 시간 목표를 조정한다.

세션 시간이 길어지는 원인은 다음 항목에서 주로 발생할 수 있다.

- 자원 생산 속도가 느림
- 유닛 이동 속도가 느림
- AI 공격 타이밍이 늦음
- 승리 조건이 너무 넓음
- 방어가 공격보다 지나치게 강함
- 맵이 지나치게 큼

## MVP 필수 요소

| 영역 | 필수 구현 내용 |
|---|---|
| 카메라 | 2D 탑다운, 이동, 줌 |
| 입력 | 마우스 선택, 드래그 박스 선택, 우클릭 이동/공격 |
| 자원 | 최소 1종 자원 |
| 일꾼 | 자원 채집, 복귀, 반복 채집 |
| 건물 | 본진, 생산 건물 |
| 유닛 | 일꾼 1종, 전투 유닛 최소 3종 |
| 생산 | 건물에서 유닛 생산 |
| 전투 | 자동 공격, 사거리, 체력, 공격력 |
| 상성 | 간단한 유닛 간 강약 관계 |
| AI | 자원 채집, 유닛 생산, 공격 타이밍 |
| 승패 | 상대 주요 건물 파괴 또는 적 전멸 |
| UI | 자원 표시, 선택 정보, 생산 버튼 |
| 맵 | 1개 테스트 맵 |

## 자원 구조

추후 결정해야 할 항목:

- 자원 종류는 1종인가, 2종인가?
- 자원은 맵에 배치된 지점에서 채집하는가?
- 자원 지점은 고갈되는가?
- 일꾼이 직접 자원을 운반하는가?
- 자원 저장 건물이 필요한가?
- 확장 기지의 필요성이 있는가?

MVP 권장안:

```text
자원 1종
일꾼 직접 채집
본진으로 복귀해 자원 반납
자원 지점은 고갈 가능
```

## 건물 구조

추후 결정해야 할 항목:

- 건물은 일꾼이 직접 건설하는가?
- 건물 건설 시간이 있는가?
- 건물 배치 제한이 있는가?
- 본진 건물이 파괴되면 패배하는가?
- 생산 건물은 몇 종류로 나눌 것인가?
- 기술 건물이나 업그레이드 건물을 둘 것인가?

MVP 권장 구성:

| 건물 | 역할 |
|---|---|
| 본진 | 일꾼 생산, 자원 반납, 핵심 승패 조건 |
| 병영 | 기본 전투 유닛 생산 |
| 기술 건물 | 선택 사항, 유닛 해금 또는 강화 |

## 유닛 구조

추후 결정해야 할 항목:

- 유닛의 장갑 유형은 나눌 것인가?
- 공중 유닛을 둘 것인가?
- 유닛 충돌 크기를 적용할 것인가?
- 유닛별 스킬을 둘 것인가?
- 유닛 생산 인구 제한을 둘 것인가?

MVP 권장 구성:

| 유닛 | 역할 |
|---|---|
| 일꾼 | 자원 채집, 건물 건설 |
| 기본 전투 유닛 | 평균적인 성능의 기준 유닛 |
| 돌격 유닛 | 빠른 이동과 근접 압박 |
| 원거리 유닛 | 긴 사거리와 낮은 체력 |

## 전투 규칙

추후 결정해야 할 항목:

- 공격은 자동 공격인가, 수동 명령 중심인가?
- 공격 사거리를 어떻게 표현할 것인가?
- 시야 시스템을 둘 것인가?
- 공격 쿨타임과 투사체 속도를 둘 것인가?
- 아군 오사가 있는가?
- 고지대, 엄폐, 지형 보너스를 둘 것인가?

MVP 권장안:

```text
자동 공격 사용
유닛별 사거리 적용
체력과 공격력 기반 전투
간단한 공격 쿨타임 적용
아군 오사 없음
지형 보너스 없음
```

## 상성 구조

MVP에서는 복잡한 수치보다 역할이 명확한 상성이 중요하다.

예시:

| 관계 | 의도 |
|---|---|
| 돌격 유닛 > 원거리 유닛 | 접근에 성공하면 원거리 유닛을 제압 |
| 원거리 유닛 > 기본 전투 유닛 | 거리 유지 시 유리 |
| 기본 전투 유닛 > 돌격 유닛 | 정면 교전에서 안정적 |

상성은 절대적인 승패가 아니라, 수량, 위치, 컨트롤에 따라 뒤집힐 수 있어야 한다.

## AI 구조

MVP AI의 목표는 사람처럼 완벽하게 플레이하는 것이 아니라, 매치의 상대가 되어 기본 루프를 압박하는 것이다.

필수 행동:

- 자원 채집
- 일꾼 유지
- 유닛 생산
- 일정 병력 이상일 때 공격
- 주요 건물 방어
- 패배 조건 처리

후속 확장:

- 정찰
- 확장 기지 건설
- 유닛 조합 변경
- 플레이어 빌드 대응
- 난이도 단계

## 승리와 패배 조건

MVP 권장 승리 조건:

```text
상대 본진 건물 파괴 시 승리
```

보조 조건:

```text
상대 유닛과 건물을 모두 제거하면 승리
```

추후 고려 가능한 조건:

- 특정 거점 점령
- 일정 시간 생존
- 자원 우위 달성
- 보스 또는 핵심 오브젝트 파괴

## 진행 구조

MVP 진행 구조:

```text
매치 시작
-> 초기 일꾼과 본진 배치
-> 자원 채집
-> 생산 건물 건설
-> 전투 유닛 생산
-> AI와 교전
-> 기지 확장 또는 공격 강화
-> 적 본진 파괴
-> 승리/패배 화면
```

## UI와 UX

필수 UI:

- 자원 표시
- 선택 유닛/건물 정보
- 체력 표시
- 생산 버튼
- 생산 진행 상태
- 미니맵 여부는 추후 결정
- 승리/패배 화면

조작 UX에서 중요한 항목:

- 선택이 명확해야 한다.
- 명령 반응이 즉각적이어야 한다.
- 유닛이 어디로 가는지 알아보기 쉬워야 한다.
- 생산 가능 여부와 부족한 자원이 명확해야 한다.
- 전투 중 어떤 유닛이 피해를 받는지 읽을 수 있어야 한다.

## 카메라와 조작

PC 우선 조작:

- 마우스 좌클릭: 단일 선택
- 마우스 드래그: 범위 선택
- 마우스 우클릭: 이동 또는 공격 명령
- 키보드: 카메라 이동, 단축키, 그룹 지정
- 마우스 휠: 줌

모바일 추후 검토:

- 탭 선택
- 드래그 선택 또는 다중 선택 UI
- 터치 이동 명령
- 핀치 줌
- 화면 가장자리 카메라 이동 대체 방식

## 세계관과 분위기

추후 결정해야 할 항목:

- 시대 배경
- 장소
- 진영 정체성
- 기술 수준
- 전쟁의 이유
- 플레이어가 맡는 역할
- 분위기와 감정 목표

가능한 방향:

- SF 군사 전략
- 중세 판타지 전쟁
- 포스트 아포칼립스 생존 전쟁
- 현대 또는 근미래 용병전
- 외계 행성 개척전
- 마법과 기계가 섞인 하이브리드 세계

## 아트 방향

추후 결정해야 할 항목:

- 2D 탑다운 또는 2D 쿼터뷰 스프라이트 스타일
- 현실적 비율 또는 과장된 실루엣
- 진영별 색상 체계
- 유닛 가독성 기준
- 건물 크기와 형태 언어
- UI 색상과 정보 밀도

MVP 권장안:

```text
임시 2D 스프라이트 또는 단순 색상 블록 사용
유닛 종류별 색상과 실루엣 차이 우선
전투 가독성 우선
고품질 아트는 후순위
```

## 사운드 방향

추후 결정해야 할 항목:

- 배경 음악 분위기
- 전투 효과음 스타일
- 선택/명령 음성 여부
- 경고음
- 건설 및 생산 완료 알림

MVP 권장안:

```text
명령음, 공격음, 피격음, 생산 완료음, 승패 효과음 정도만 우선 적용
```

## 개발 범위 관리

1인 개발 기준에서는 범위를 작게 유지하는 것이 중요하다.

MVP에서 만들 것:

- AI 1대1 매치
- 기본 자원 루프
- 기본 생산 루프
- 기본 전투 루프
- 간단한 상성
- 승패 판정

MVP 이후로 미룰 것:

- 멀티플레이
- 캠페인
- 다수 진영
- 고급 그래픽
- 복잡한 업그레이드
- 고급 AI
- 모바일 최적화
- 랭킹 및 계정 시스템

## 권장 개발 순서

```text
1. 카메라와 테스트 맵
2. 유닛 선택 및 이동
3. 자원 채집
4. 건물 건설
5. 유닛 생산
6. 전투 시스템
7. 간단한 상성
8. AI 생산 및 공격
9. 승패 판정
10. UI 정리
11. 밸런스 조정
```

## 기획상 다음 결정 항목

다음 단계에서는 아래 항목을 우선 결정한다.

1. 자원은 1종으로 시작할지, 2종으로 시작할지
2. 일꾼이 건물 건설까지 담당할지
3. 본진 파괴를 승리 조건으로 확정할지
4. 전투 유닛 3종의 구체적인 역할과 이름
5. 맵 크기와 자원 배치 방식
6. AI의 첫 공격 타이밍
7. 업그레이드 시스템을 MVP에 포함할지

## 현재 기준의 MVP 완료 정의

```text
플레이어가 자원을 채집하고, 건물을 짓고, 유닛을 생산하고, AI와 전투하여 적 본진을 파괴하거나 패배할 수 있으면 MVP 완료로 본다.
```
